# New Patch

One pull request adopts one Patch. The detail of each step lives in three documents this skill points at: the New Patch loop and the Curation rules of `packages/reforged-types/AGENTS.md`, "The `reforged.patch` field" and "Choosing the bump for a Patch" of `docs/release.md`, and the Nullability sweep of `probe/README.md`. Read both sections of the nested `AGENTS.md` before step 1. Run every command from the repository root, on a branch from `master`.

## Steps

1. **Vendor and generate.** Take the jass-history tag you were handed or the issue names; for a Build without its tag, find it in `gh api --paginate "repos/Luashine/jass-history/tags?per_page=100" --jq ".[].name"`. Run `pnpm typings:generate <tag>` and keep its whole output, stdout and stderr: it is the failure list. Done when the output prints `Vendored <tag>: Patch <Build> at commit <sha>` and `packages/reforged-types/vendor/<Build>/` holds the three Patch files and `provenance.json`, next to the previous Build's folder (loop step 1).
2. **Read the failure list.** Sort its items as loop step 2 says: the declarations only the new Patch has, then each checklist item. Done when every item has its kind and the fix it needs.
3. **Curate.** Write one Overlay entry per missing Native at the path its item prints, by the Curation rules; fix the other error items as loop step 2 says. Done when every error item of the failure list has its entry or fix; step 4 proves it.
4. **Regenerate.** Run `pnpm typings:generate` without the tag, returning to step 3 for whatever it still prints. Done when it exits 0 and every remaining warning is accounted for (loop step 5).
5. **Re-run the Nullability sweep.** Run `pnpm probe:run <slice>`, then `pnpm probe:nullability-report <slice>`, for every Slice of the sweep (`probe/probes/nullability-*.ts`): all of them on every Patch, so the report stays on one Build, as [Running a Probe run](../../../probe/README.md#running-a-probe-run) says. Keep each Slice's committed `skip` list: a case that stopped crashing can only open a narrowing, never a block; a new crash follows [the crash loop](../../../probe/README.md#the-crash-loop).
   - `probe:run` exits 4, naming both Builds, when the game client is not on the Build adopted. Client behind: stop and give the human a checklist to update the game through the Battle.net app, its configuration never edited, then run again. Client ahead (a Build older than the live one): skip the re-run of that Build, and the pull request says so.
   - A Native new in the Patch, curated nullable with its `returns.family` at step 3, joins its family's Slice declaration (its last part, or a new part past 1,000 cases), its cases expanded by its family's generator. A `non-null (evidence)` verdict narrows it here: additive.
   - On a `mismatch`, widen the entry: `nullable: true`, its `notes` naming the case and the Build. Stop and tell the human before committing the widening; it goes on the record of step 6 as **breaking**, and the changeset carries the major.
   - Each report prints the changes from the section it replaced when that one was written under another Build: keep them for the pull request.
   - A Crashing case new on the Patch, or gone from it (a crashed row of a report added or gone), updates `probe/crashing-cases.json`, as [the crash loop](../../../probe/README.md#the-crash-loop) says: a new one gets a record with its Guard or the reason it is excluded, a gone one loses its record. `pnpm check` fails until the file and the report agree.

   Done when every Slice's section names the new Build (or the re-run was skipped for a client ahead), every `mismatch` is widened, every crashed row has its record in `probe/crashing-cases.json`, and the changes of every Slice are kept.

6. **Review the generated diff.** Compare the new output with the old: `git diff -- packages/reforged-types/<Game version> packages/reforged-types/<Game version>.d.ts packages/reforged-types/async-natives.json` when the new Build keeps the Game version; when it opens a new one, `git diff --no-index packages/reforged-types/<old Game version> packages/reforged-types/<new Game version>` and `git diff -- packages/reforged-types/async-natives.json`. Find every signature change (a parameter, a return type, a nullability, an async flag), removal and hierarchy change (the `extends` of a handle type). Record each in a list, the record, as **breaking** when code that compiled against the old Typings may no longer compile, else **additive**; the changesets and the pull request carry it. Done when every changed declaration of the diff is on the record with its verdict.
7. **Cover the new Natives.** Run `pnpm coverage:report`. Wrap each new Native a Wrapper owns with the [add-wrapper](../add-wrapper/SKILL.md) skill, or exclude it in the report's exclusions with the source the amendment of ADR 0008 requires and its tracking issue (`gh issue create` when none exists). Done when the report lists none of the new Natives as missing.
8. **Bump `reforged.patch`.** Move the fields and the rest of the Patch metadata as loop step 6 says, and each field the list "Which fields move" of "Choosing the bump for a Patch" names. Done when `pnpm release:check-patches` exits 0 naming the new Build for `reforged-types` and `reforged-ts`, and every item of loop step 6 is done.
9. **Write the changesets.** Give each package its bump by "Choosing the bump for a Patch" of `docs/release.md`, from the record of step 6 and the Wrappers of step 7, and name each breaking change in the text. Add them without the prompt ("Adding a changeset"). Done when the changesets give each package the bump the rules set and name every breaking change of the record.
10. **Check and commit.** Run `pnpm check` and `pnpm --filter reforged-types verify`, then commit as loop step 8 says and run `pnpm release:check-changeset`, which reads the committed changes. Done when all three exit 0 (`pnpm check` runs `typings:check`) and `git status` is clean.
11. **Open the pull request** against `master` with `gh pr create`. Its body turns the failure list into a checklist, one checked box per item with its fix, and carries the record of step 6, the outcome of step 7 and the changes of step 5; it closes the "New Patch detected" issue when there is one. Done when the pull request exists and every item of the failure list is a checked box.

## Done

The Patch is adopted when `pnpm typings:generate` and `pnpm typings:check` exit 0, the coverage report lists no new Native as missing, `pnpm release:check-patches` names the new Build, every Slice of the Nullability sweep ran on it (or was skipped for a client ahead), and the changesets of step 9 are committed.
