# MPQ writer vs a 3.0.0 editor map folder (w3i version 39)

Research note for ticket [#32](https://github.com/phmilk/reforged-ts/issues/32). Facts only, no decision. Continues section 1.4 of [template-landscape.md](https://github.com/phmilk/reforged-ts/blob/research/template-landscape/docs/research/template-landscape.md) (how `wc3-ts-template` packs a map folder with `mdx-m3-viewer-th`).

Written 2026-09-23. Everything below was run locally on Windows 11 with Node v24.14.0 / npm 11.9.0 against `mdx-m3-viewer-th@5.13.4` (the version the template pins), in a throwaway directory outside the repo. The game-load step could not be run by the author; it is the checklist in section 7.

## 0. Summary

| Question (from the ticket) | Answer |
|---|---|
| Does `War3Map.save()` throw on a v39 `war3map.w3i`? | **Yes.** `ByteStream: readUint8Array: premature end - want 8 bytes but have 0`, thrown from `Player.load` via `getMapInformation()`. No archive is produced. |
| Does the upstream w3i parser misread v39? | Yes. Correct through `campaignBackground`; everything from `loadingScreenModel` on is misaligned by the new v39 field at offset 0x8d (section 3). |
| Does the produced archive keep `war3map.w3i` byte-for-byte? | **Yes** (with either fallback): same 375 bytes, sha256 `4eb20f96…c8d9`. All 17 input files are byte-identical inside the archive. |
| Archive contents | 19 entries: the 17 input files + `war3map.imp` (generated by `import()`) + `(listfile)`. `(attributes)` absent. No `HM3W` prefix; `MPQ\x1a` at offset 0. 21,476 bytes. |
| Round trip | Re-opening the produced `.w3x` works (from an in-memory `Uint8Array`); re-saving needs the same fallback (upstream `save()` throws again on the same w3i); second archive re-opens, w3i still identical, 21,487 bytes (the regenerated `(listfile)` now lists itself). |
| `game_data_version` value written by the 3.0.0 editor | **2** (the slot the upstream parser calls `unknown1`, at offset 0xdb). w3i file version **39**, editor version 7000, game version `3.0.0.24268`. |
| Smaller fallback | Treating `war3map.w3i` as opaque bytes in `save()` (8 lines in the build script, or ~6 lines in `map.ts`) versus a v39 parser fork (~80–100 lines across `w3i/file.ts` and `w3i/player.ts` plus maintaining a fork). Both produce byte-identical archives (section 5). |
| Does the game load it? | Not run here. Checklist in section 7; files are at the paths in section 6. |

## 1. Inputs

- Map folder: `reforged-ts-probe-test.w3m\`, a blank map saved as a folder by the Warcraft III 3.0.0 World Editor (attached to [#9](https://github.com/phmilk/reforged-ts/issues/9)). 17 regular files: `conversation.json`, `war3map.doo`, `war3map.lua`, `war3map.mmp`, `war3map.shd`, `war3map.w3c`, `war3map.w3e`, `war3map.w3grp`, `war3map.w3i`, `war3map.w3l`, `war3map.w3r`, `war3map.wct`, `war3map.wpm`, `war3map.wtg`, `war3map.wts`, `war3mapMap.blp`, `war3mapUnits.doo`. Two empty directories (`_Locales\`, `war3mapImported\`) contain no files and are therefore not packed. No `war3map.imp` and no object-data files (`w3u`, `w3a`, …) exist in the folder.
- `war3map.w3i`: 375 bytes, starts with int32 `39`.
- Library: `mdx-m3-viewer-th@5.13.4` from npm (`dist/cjs/parsers/w3x/map.js`, `dist/cjs/parsers/w3x/w3i/file.js`, `dist/cjs/parsers/w3x/w3i/player.js`, `dist/cjs/parsers/mpq/archive.js`). The packing calls reproduce `createMapFromDir` of `wc3-ts-template/scripts/build.ts` exactly: `new War3Map()`, `map.archive.resizeHashtable(files.length)`, `map.import(relativePath, fs.readFileSync(file))` for every file (recursive), `map.save()`.
- Reference layouts for v39: wc3libs commit [52924b921f](https://github.com/inwc3/wc3libs/commit/52924b921f) ("Support W3I format version 39") and HiveWE commit [9f04c14](https://github.com/stijnherfst/HiveWE/commit/9f04c14) ("Update map file parsers"). Read as raw `.diff`.

### 2.2 `patch-v39.js` (the other fallback: a v39-aware parser, monkey-patched, so the unchanged upstream `save()` works)

```js
// Fallback A for ticket #32: v39-aware w3i parser (monkey-patched load() only) so upstream War3Map.save() works unchanged.
// usage: node patch-v39.js <mapFolder> <outDir>
const fs = require("fs");
const path = require("path");
const crypto = require("crypto");
const War3Map = require("mdx-m3-viewer-th/dist/cjs/parsers/w3x/map").default;
const War3MapW3i = require("mdx-m3-viewer-th/dist/cjs/parsers/w3x/w3i/file").default;
const Player = require("mdx-m3-viewer-th/dist/cjs/parsers/w3x/w3i/player").default;
const BinaryStream = require("mdx-m3-viewer-th/dist/cjs/common/binarystream").default;
const sha = (b) => crypto.createHash("sha256").update(b).digest("hex");

const SRC = process.argv[2], OUT = process.argv[3];
const files = fs.readdirSync(SRC, { withFileTypes: true }).filter((e) => e.isFile()).map((e) => e.name);

// --- patch Player.load: one extra int32 for version >= 39 (HiveWE: hud_skin after race; wc3libs: hudSkin after startPosFixed) ---
Player.prototype.load = function (stream, version) {
  this.id = stream.readInt32();
  this.type = stream.readInt32();
  this.race = stream.readInt32();
  if (version >= 39) this.hudSkin = stream.readInt32();
  this.isFixedStartPosition = stream.readInt32();
  this.name = stream.readNull();
  stream.readFloat32Array(this.startLocation);
  this.allyLowPriorities = stream.readUint32();
  this.allyHighPriorities = stream.readUint32();
  if (version > 30) stream.readUint8Array(this.unknown1);
};

// --- patch War3MapW3i.load: v39 additions = 4 B after campaignBackground, 24 B after lightEnvironmentTileset, 40 B after minCameraZoom ---
const origLoad = War3MapW3i.prototype.load;
War3MapW3i.prototype.load = function (buffer) {
  const stream = new BinaryStream(buffer);
  this.version = stream.readInt32();
  if (this.version < 39) return origLoad.call(this, buffer);
  this.saves = stream.readInt32();
  this.editorVersion = stream.readInt32();
  stream.readUint32Array(this.buildVersion);
  this.name = stream.readNull(); this.author = stream.readNull(); this.description = stream.readNull(); this.recommendedPlayers = stream.readNull();
  stream.readFloat32Array(this.cameraBounds); stream.readInt32Array(this.cameraBoundsComplements); stream.readInt32Array(this.playableSize);
  this.flags = stream.readUint32(); this.tileset = stream.readBinary(1); this.campaignBackground = stream.readInt32();
  this.alphaTileMinimapColor = stream.readInt32();                                   // v39 (HiveWE: loading_screen_source)
  this.loadingScreenModel = stream.readNull(); this.loadingScreenText = stream.readNull(); this.loadingScreenTitle = stream.readNull(); this.loadingScreenSubtitle = stream.readNull();
  this.loadingScreen = stream.readInt32();
  this.prologueScreenModel = stream.readNull(); this.prologueScreenText = stream.readNull(); this.prologueScreenTitle = stream.readNull(); this.prologueScreenSubtitle = stream.readNull();
  this.useTerrainFog = stream.readInt32(); stream.readFloat32Array(this.fogHeight); this.fogDensity = stream.readFloat32(); stream.readUint8Array(this.fogColor);
  this.globalWeather = stream.readInt32(); this.soundEnvironment = stream.readNull(); this.lightEnvironmentTileset = stream.readBinary(1);
  this.terrainFogV39 = stream.readUint8Array(new Uint8Array(24));                    // v39: fogStyle u8, drawOverSky u8, 5 floats, skyDisplay u8, timeOfDay u8
  stream.readUint8Array(this.waterVertexColor);
  this.scriptMode = stream.readUint32(); this.graphicsMode = stream.readUint32(); this.unknown1 = stream.readUint32();
  this.defaultCameraZoom = stream.readUint32(); this.maxCameraZoom = stream.readUint32(); this.minCameraZoom = stream.readUint32();
  this.waterV39 = stream.readInt32Array(new Int32Array(10));                         // v39: 10 water ints
  for (let i = 0, l = stream.readInt32(); i < l; i++) { const p = new Player(); p.load(stream, this.version); this.players[i] = p; }
  const Force = require("mdx-m3-viewer-th/dist/cjs/parsers/w3x/w3i/force").default;
  for (let i = 0, l = stream.readInt32(); i < l; i++) { const f = new Force(); f.load(stream); this.forces[i] = f; }
  // upgrade / tech / random tables: counts only (all 0 in the probe map); a real fork would keep the upstream loops here.
  this._tail = [stream.readInt32(), stream.readInt32(), stream.readInt32(), stream.readInt32()];
  this._remaining = stream.remaining;
};

const w3iBytes = fs.readFileSync(path.join(SRC, "war3map.w3i"));
const w3i = new War3MapW3i(); w3i.load(w3iBytes);
console.log("patched parse:", { version: w3i.version, build: w3i.getBuildVersion(), name: w3i.name, alphaTileMinimapColor: w3i.alphaTileMinimapColor, loadingScreen: w3i.loadingScreen, scriptMode: w3i.scriptMode, graphicsMode: w3i.graphicsMode, gameDataVersion: w3i.unknown1, zoom: [w3i.defaultCameraZoom, w3i.maxCameraZoom, w3i.minCameraZoom], water: Array.from(w3i.waterV39), players: w3i.players.map((p) => ({ id: p.id, type: p.type, race: p.race, hudSkin: p.hudSkin, fixed: p.isFixedStartPosition, name: p.name, start: Array.from(p.startLocation) })), forces: w3i.forces.map((f) => ({ flags: f.flags, mask: f.playerMasks, name: f.name })), tailCounts: w3i._tail, remaining: w3i._remaining });

const map = new War3Map();
map.archive.resizeHashtable(files.length);
for (const rel of files) map.import(rel, fs.readFileSync(path.join(SRC, rel)));
const buf = map.save();
fs.writeFileSync(path.join(OUT, "probe-v39-parser.w3x"), buf);
const fb = fs.readFileSync(path.join(OUT, "probe-opaque-w3i.w3x"));
console.log("upstream save() with patched parser OK:", buf.byteLength, "bytes; byte-identical to opaque fallback build:", sha(Buffer.from(buf)) === sha(fb));
```

Upstream parser (`w3i/file.js`, `w3i/player.js` in 5.13.4) versus this layout:

- It has no `version > 33` branch; the newest conditional is `version > 32` (camera zooms). It reads version, saves, editorVersion, build version, the four strings, camera bounds, margins, size, flags, tileset and `campaignBackground` correctly (the values printed above are right up to `campaignBackground: -1`).
- At 0x08d it expects `loadingScreenModel` (a null-terminated string) but finds the v39 int32 `128` (`80 00 00 00`), so it reads the string `"\x80"` and is off by three bytes from there on. Every later field is garbage (`loadingScreen: 33554432`, `scriptMode: 473956352`, `unknown1: 2147483718`, player count `0x01ffffff`), and it throws `premature end` inside the third `Player.load`.
- The v39 additions the parser would need: +4 bytes after `campaignBackground`, +24 bytes between `lightEnvironmentTileset` and `waterVertexColor`, +40 bytes after `minCameraZoom`, and +4 bytes per player (68 bytes fixed + 4 per player; 375 − 68 − 4 = 303 bytes is what the upstream layout would produce for this map).
- `getBuildVersion()` returns 300 for this file, so even a successful parse takes the "no `HM3W` header" branch of `save()`.

Reference naming differences (both commits read the same bytes): wc3libs [52924b921f](https://github.com/inwc3/wc3libs/commit/52924b921f) `read_0x27` reads `campaignBackgroundIndex`, then `alphaTileMinimapColor`, …, after `tilesetLightEnv`: `terrainFogStyle` (ubyte), `drawTerrainFogOverSky` (ubyte), five floats, `skyDisplay` (ubyte), `timeOfDay` (ubyte), then water colour, `scriptLang`, `graphics`, `gameDataVersion`, three zooms, ten water ints; in `Player.read_0x27`: `startPosFixed` then `hudSkin`. HiveWE [9f04c14](https://github.com/stijnherfst/HiveWE/commit/9f04c14) `map_info.ixx`: `loading_screen_number`, then `if (version >= 39) loading_screen_source`, …, after `weather_id`: `unknown_fog1` (int), `fog_linear_start/end`, `fog_max_opacity`, `unknown_fog2`, `unknown_fog3`, then sound env / light env; after `min_cam_distance` the ten water ints; player: `race`, `if (version >= 39) hud_skin`, `fixed_start_position`. HiveWE also names flag bits `use_terrain_fog 0x2000`, `requires_expansion 0x4000`, `override_hd_water_color 0x800000`, `alpha_tile_default_minimap_color 0x1000000`, `dynamic_minimap 0x2000000`; this map's flags 0x9c10 set none of the three new bits.

## 4. `game_data_version`

- The slot after `graphicsMode` (upstream `unknown1`, offset 0x0db) holds **2** in this file. wc3libs master defines `enum GameDataVersion { ROC(0), TFT(1), FORSAKEN_KINGDOM(2), UNKNOWN(-1) }` ([W3I.java L784-788](https://github.com/inwc3/wc3libs/blob/master/src/main/java/net/moonlightflower/wc3libs/bin/app/W3I.java)); at commit 52924b921f the v39 reader still mapped the slot as `== 0 ? ROC : TFT`, and the raw-value preservation was added afterwards (`_gameDataVersionRaw`, `read_0x27` calls `setGameDataVersion(stream.readUInt32("gameDataVersion"))` on master).
- So a blank map created and saved by the 3.0.0 editor is written as the Forsaken Kingdom data set. Because both fallbacks store `war3map.w3i` byte-for-byte, the packed archive carries the same value; the writer neither reads nor changes it.
- The other "data set" slot at 0x095 (old-spec "used game data set", upstream field `loadingScreen`) also holds 2 in this file.

## 8. Other observations (not asked, found on the way)

- `War3Map.load()` in 5.13.4 needs a plain `Uint8Array`/`ArrayBuffer`, not a Node `Buffer`. `archive.load()` calls `bytes.slice(...)` for the hash and block tables and then uses `.buffer` of the result; Node's `Buffer.prototype.slice` returns a view, so `.buffer` is the whole file and the table is decrypted from the wrong bytes. Loading `probe.w3x` via `fs.readFileSync()` directly yielded one bogus entry `File00000000`; loading `probe-roundtrip.w3x` the same way threw `RangeError: byte length of Uint32Array should be a multiple of 4` (21,487 is not a multiple of 4). `new Uint8Array(fs.readFileSync(p))` loads both correctly. This does not affect the template's packing path (it only calls `import()`/`set()` with Buffers, and those round-tripped byte-identical), only code that re-opens a `.w3x` in Node.
- The upstream `War3Map.save()` builds the whole archive (`archive.save()`) before parsing the w3i, so the thrown error discards a fully built archive; nothing about the MPQ writer itself fails on this map.
