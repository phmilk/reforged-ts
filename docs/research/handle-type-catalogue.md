# Handle-type catalogue

What a Probe needs to call each of the 394 handle-returning Natives of `common.j` 3.0.0.24268: for each handle type, the Natives that give a live Handle of it in the Probe map and the ones that make it stale; for each Native, the context it answers in and a proposed family. It answers #362 for the wayfinder map #359, and feeds the families ticket #363 and the planning of the Slices of the [Nullability sweep](../../CONTEXT.md). The families here are proposals, not decisions, and nothing here changes the Overlay.

## Method and sources

- **The 394.** A script parsed the vendored `packages/reforged-types/vendor/3.0.0.24268/common.j` (jass-history tag `Reforged-v3.0.0.24268-w3-3a9d8f2`, sha256 `7561e8be…f8fbb`, from its `provenance.json`). A handle type is `handle` or any `type X extends …` (139 declarations). Of the 1,681 Natives, 394 return a handle type, 88 of them named `Convert*`, and 26 have `returns.nullable: false` in the Overlay (`packages/reforged-types/overlay/common.j/functions/`) at `0197e9f`, the counts #359 gives. Every Native has an Overlay entry.
- **Types.** 136 handle types appear in those 394 as a return or a handle-typed parameter: all 136 are returned by one of them, and 38 are also parameters. `handle`, `agent`, `buff` and `metakeytype` appear in neither.
- **Contexts.** The section comments of the vendored `common.j`, which name the event each event response belongs to (`// EVENT_PLAYER_UNIT_DEATH` above `GetDyingUnit`), cited by line in the table below.
- **jassdoc** ([lep/jassdoc](https://github.com/lep/jassdoc) at `8610958`, 2026-09-17), for facts only: which Natives return nothing on failure, which crash, which events a response belongs to. Its prose is not copied, since it has no licence; each Native's page is `https://lep.duckdns.org/jassbot/doc/<Native>`.
- **The library.** The Wrappers under `packages/reforged-ts/src/handles/` and the event descriptors under `src/events/` (their `@native` tags name 232 of the 394), and `wrapper-coverage/exclusions.json`.
- **The Probe map.** `probe/probe.w3m/war3map.lua` and its object files: one user, Player(0), start location 0 at (-1408, 1728), no preplaced unit, destructable, region or camera. Its Melee Initialization runs as the Template's does (`MeleeInitVictoryDefeat` replaced, `probe/README.md`), so `MeleeStartingUnits` gives Player(0) a Town Hall and five peasants at its start location: with no gold mine near it, `MeleeStartingUnitsHuman` in the vendored `blizzard.j` places them there (assuming the game picks Human, the race `config` prefers).
- **Slice 1.** `probe/probes/nullability-slice-1.ts`, its Fixtures in `probe/probes/nullability/fixtures.ts` and its section of [`nullability-sweep.md`](nullability-sweep.md).

What is not established is marked "to measure" or "to establish" in the tables: a fact for a Probe run, not for this catalogue.

"Only in context" counts the Natives whose live return needs a context: an event, an enum or filter callback, a game state built first, or the local mouse. By the map's rules a call outside that context is a valid case, and a `nil` there proves the Native nullable.

The families, as proposed for #363:

- **converter**: the 88 `Convert*`, an integer to an enum-like handle.
- **enum-getter**: a getter that returns an enum-like handle (`GetPlayerColor`, `GetGameSpeed`, `GetItemType`).
- **constructor**: a Native that creates an object and returns its handle. It holds two groups #363 may want to split off: the 26 registrations (`TriggerRegister*`, `BlzTriggerRegister*`), which return the `event`, and the 36 destructable creators, one Native over every combination of `Z`, `Dead`, skin, pitch and roll, and colour.
- **event-response**: a getter that reads the running event (`GetTriggerUnit`, `GetSpellAbility`), `GetExpiredTimer` and `GetTriggeringTrigger` included.
- **callback-getter**: `GetFilter*` and `GetEnum*`, which read the object an enum or a filter is on.
- **lookup**: a handle found by an id, an index, a name or keys (`Player`, `UnitItemInSlot`, `BlzGetFrameByName`, the 39 `Load*Handle`).
- **property-getter**: the handle one object holds (`GetOwningPlayer`, `GetUnitRallyUnit`, `BlzFrameGetParent`).
- **other**: `GetLocalPlayer`, and three item actions that return the item they moved or made (`UnitAddItemById`, `UnitRemoveItemFromSlot`, `UnitUnequipItemFromSlot`).

### Findings

- **Every argument type has a live Fixture in the empty map.** Each of the 38 handle types the 394 take as a parameter has a Native that creates a live one from nothing (`CreateTrackable`, `DialogAddButton`, `InitGameCache`, `Convert*` for the enum-like ones), so no Native lacks a live argument. Where it fails is the live return: 9 Natives cannot return a live handle without a player or a special game.
- **Out of reach of a Probe run alone.** `GetTournamentFinishNowPlayer` answers only in a Battle.net tournament game. `GetWinningPlayer` answers in `EVENT_GAME_VICTORY`, which ends the game, so the Probe run: only a step after `END` could record it.
- **Needs input.** `GetTriggeringTrackable` (the mouse on a trackable), `GetClickedButton` and `GetClickedDialog` (a click on a dialog button, or its hotkey), `BlzGetTriggerPlayerMousePosition`, `BlzGetTriggerPlayerMouseButton`, `BlzGetTriggerPlayerKey` and `BlzGetMouseFocusUnit`. No Native fires these events; the agent can post a key to the game window as it does for the loading screen (#359), which reaches the dialog hotkey and the key event, not the mouse ones. Their out-of-context case needs no input, and proves them nullable if it returns `nil`.
- **The 3.0.0 equipment Natives.** `GetEquippedItem`, `GetUnequippedItem`, `UnitUnequipItemFromSlot`, `UnitItemInBagSlot` and `UnitItemInEquipmentSlot` need an item the game treats as equipment, and which item ids those are in 3.0.0.24268 is not established: no source read here lists them. Their out-of-context and empty-slot cases need none.
- **Cases that may crash.** jassdoc reports two calls that can crash the game: `GetExpiredTimer` with no expired timer, which is exactly its out-of-context case, and `BlzFrameGetChild` with an invalid index. `BlzCreateFrameByType` can crash for some frame types created without their FDF fields. A Slice runs these last, as Slice 1 ran its destroyed frame.
- **Outside its event, not nothing.** `GetOrderPointLoc` returns a location at (0, 0, 0) outside its event (jassdoc), so its out-of-context case may not prove it nullable. Slice 1 saw `TriggerAddAction` on a destroyed trigger return a handle of id 0 (Overlay notes): the case runner records both as `handle` or `odd`, never `nil`.
- **Nothing inside the context.** Some Natives return nothing inside their own event, a case with no out-of-context call: `GetKillingUnit` after `KillUnit` (no killer), `BlzGetAbsorbingItem` when the item picked up was a powerup (`common.j`), the typed target getters (`GetOrderTargetItem`, `GetSpellTargetUnit`) on a target of another type, and `GetTriggerEventId` in a run by `TriggerExecute`.
- **Documented `nil` returns.** jassdoc already reports a `nil` return, a case a Slice can reproduce, for `Player` (an index out of range, on Reforged), `CreateDestructable`, `CreateDestructableZ`, `CreateDeadDestructable` and `CreateDeadDestructableZ` (an id that fails), `CreateCorpse` (a unit type with no corpse), `UnitAddItemById` (a unit that cannot take the item, a footman), `UnitRemoveItemFromSlot` and `UnitItemInSlot` (an empty slot), `BlzGroupUnitAt` and `FirstOfGroup` (a removed member), `RestoreUnit` (nothing stored), `AddLightning` and `AddLightningEx` (`checkVisibility` true and the points unseen), `GetExpiredTimer` (a timer destroyed before its callback), `GetTriggerUnit` and `GetTriggerWidget` (outside their event).
- **Handles that never go stale.** No Native destroys a `player`, `camerasetup`, `trackable`, `gamecache` or any of the 90 enum-like types. For `event`, `button`, `quest` and `hashtable` it is unknown: no Native destroys an `event`, a `button` goes with its dialog, `DestroyQuest` destroys the quest's items and not the quest itself (jassdoc), and `FlushParentHashtable` empties a hashtable whose handle may or may not survive.
- **Converters with no constant.** `common.j` declares no constant of six enum-like types: `mapsetting`, `mapvisibility` and the four `ability*levelarrayfield` types. Their converters have no integer of known meaning to call them with; any integer is the case.
- **The Overlay today against the families.** The 26 non-null entries are 4 converters, 6 enum-getters, 12 constructors, 3 property-getters and `GetLocalPlayer`; no lookup, event response or callback getter is non-null. 137 of the 394 only answer in a context, and their out-of-context case is the cheapest test of each.

## The tables

The tables of the next two sections are pipe tables a script can read: one row per type or per Native, the values of the coded columns from the closed sets below, `/` in place of a pipe inside a cell.

- **Context**: `anywhere`, `event`, `callback`, `local`, `state`, `ai`.
- **Only in context**: `yes` or `no`.
- **Family**: `converter`, `enum-getter`, `constructor`, `event-response`, `callback-getter`, `lookup`, `property-getter`, `other`.
- **Reach**: `direct`, `built`, `timed`, `input`, `none`, `ends-game`.
- **Overlay nullable**: the entry's `returns.nullable` at `0197e9f`.
- **Kind** (types): `object`, a type some Native creates and some may destroy; `enum-like`, a type whose values are the `Convert*` constants.
- **Can be stale** (types): `yes`, `no` or `unknown`.

## Fixtures per type

The 136 handle types the 394 return or take, in two tables under the same header: the 46 object types, by how many of the 394 use them, then the 90 enum-like types, by name. "Returned by" and "Argument of" count the Natives of the 394 that return the type or take it as a parameter. "Live in the Probe map" gives a call that makes a live one; "Stale by" the Natives that make one dead, removed or destroyed; "In fixtures.ts" the factories of `probe/probes/nullability/fixtures.ts` that build one today.
