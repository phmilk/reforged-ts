# reforged-map

## 1.0.0-alpha.3

### Minor Changes

- [#644](https://github.com/phmilk/reforged-ts/pull/644) [`90f47f4`](https://github.com/phmilk/reforged-ts/commit/90f47f492ef93e81153dac755b433dadb5e270be) Thanks [@wyller](https://github.com/wyller)! - `openObjectData(mapFolder, { projectRoot })` opens a map folder's Object data for a tool that edits it: `objects(kind)` lists its objects as the Object Editor shows them, base and Skin files merged and names resolved, and `save(folder)` saves it to the map folder or to another folder, byte for byte (every Object data file, Skin file and `war3map.wts` comes back with the same bytes when nothing was edited). A save refuses with an `ObjectDataWriterError` of reason `"changed-on-disk"` when a file it would rewrite changed since it was read. The package now reads and writes Object data, and only reads the rest of the map folder (ADR 0015).

- [#646](https://github.com/phmilk/reforged-ts/pull/646) [`d4d96a5`](https://github.com/phmilk/reforged-ts/commit/d4d96a553f8a74e2f23f7c3bb0b1a008f1fb6b1b) Thanks [@wyller](https://github.com/wyller)! - The Object data editor's save runs the World Editor check before its first write: it refuses to write a folder the World Editor shows unsaved edits for, and its result's `worldEditor` says whether the World Editor has the folder open, so a tool can reload it there with `-launch -loadfile`. `checkWorldEditor` runs the check on its own. `save(folder, { worldEditorCheck: false })` turns it off for a folder no World Editor opens, such as the build's staged copy in `dist/`. `ObjectDataWriterError` gains the reasons `"modified-in-world-editor"` and `"world-editor-check-failed"`.

- [#648](https://github.com/phmilk/reforged-ts/pull/648) [`8c05737`](https://github.com/phmilk/reforged-ts/commit/8c05737b969fdbf276f7b4411f35d62794862b18) Thanks [@wyller](https://github.com/wyller)! - `reforged-map textconv <file>`, a git `textconv` driver of Object data: it prints an Object data file as text, one line per object and per modification, so that `git diff` of the map folder shows which object and which field a commit changed, with the old and the new value. A file it cannot read prints the reason and a hex dump, and exits 0. `objectDataText(bytes, fileName)` gives the same text. The README's "Object data in `git diff`" gives the attributes and the git configuration for a repository the Template does not set up.

## 1.0.0-alpha.2

### Minor Changes

- [#612](https://github.com/phmilk/reforged-ts/pull/612) [`6943970`](https://github.com/phmilk/reforged-ts/commit/6943970ca43b890676aa46ece085a0853d9365d9) Thanks [@wyller](https://github.com/wyller)! - `reforged-map/typescript-plugin`, a TypeScript language service plugin ([#595](https://github.com/phmilk/reforged-ts/issues/595)): on a Rawcode literal, `FourCC("h000")` or `1751543663 as Rawcode<"unit">`, the hover shows the object it names (its name, Object kind, origin, base or the map's name, race, Game data sets and constant), both objects of a Rawcode two kinds share, or the lint rule's sentence for an unknown, malformed or out-of-Game-data-set Rawcode; go to definition goes to the object's constant. It reads the map folder through the Rawcode lookup, follows a World Editor save without a build, finds the map folder under `maps/` or from its `mapFolder` option, and says in one line why when it cannot. Enable it with `"plugins": [{ "name": "reforged-map/typescript-plugin" }]` in the tsconfig's `compilerOptions`, under the Map project's own TypeScript.

## 1.0.0-alpha.1

### Minor Changes

- [#605](https://github.com/phmilk/reforged-ts/pull/605) [`8770890`](https://github.com/phmilk/reforged-ts/commit/8770890f995489449670f597882b6d3049883d8b) Thanks [@wyller](https://github.com/wyller)! - Add `openRawcodeLookup({ mapFolder, projectRoot })`, a synchronous lookup from a Rawcode to what it names, for the tools that read the map (the lint rule, the hover): known with its object or objects (Built-in, Custom or modified, with name, Object kind, race, base, Game data sets and constant), unknown with up to three suggestions one edit away, malformed, or unavailable with the reason. `gameVersion()` gives the Game version of the `reforged-builtins` index it read. It loads with `require` from a CommonJS host.

- [#598](https://github.com/phmilk/reforged-ts/pull/598) [`2281d2e`](https://github.com/phmilk/reforged-ts/commit/2281d2e0662125c01dc00221741a6a36e1d29901) Thanks [@wyller](https://github.com/wyller)! - A second entry point, `generateObjects`, generates the code of a map folder's objects ([#583](https://github.com/phmilk/reforged-ts/issues/583)). For each Custom unit of `war3map.w3u` and `war3mapSkin.w3u` (format version 3, the 3.0 World Editor's), named through `war3map.wts`, it writes a `FourCC` overload into `map-objects.d.ts`, so `FourCC("h000")` is a `Rawcode<"unit">` whose hover reads "Captain (`h000`), a Custom unit of this map, derived from Footman (`hfoo`)". It also writes a constant into `custom-units.ts`, `CustomUnits.Captain_h000`, which compiles to the integer `FourCC` returns. The seven constants modules, `custom-units.ts` to `custom-upgrades.ts`, are always written, so an import never breaks; the other six kinds are empty until they are read. Constants are named by `reforged-builtins`' rules. A Custom unit that keeps its base's name is named after its base, from the index of `reforged-builtins`, a new optional peer resolved from the Map project; without it, it is named `Unnamed`, with a warning.

- [#606](https://github.com/phmilk/reforged-ts/pull/606) [`0c33c10`](https://github.com/phmilk/reforged-ts/commit/0c33c1092afb25f870d4928fb78fc3a8fdc4e6d0) Thanks [@wyller](https://github.com/wyller)! - The Rawcode lookup reads the map's Game data set from `war3map.w3i` (its Game Data Set, Game Data Version and "Melee Map" flag, in the formats wc3libs reads, 39 the 3.0 World Editor's) and returns a Built-in object that set does not hold as `not-in-game-data-set`, with the map's set. `warnings()` gives the warnings of reading the map folder: a missing, truncated or unknown-format `war3map.w3i` gives one, and the check is then skipped.

- [#607](https://github.com/phmilk/reforged-ts/pull/607) [`6a51d5f`](https://github.com/phmilk/reforged-ts/commit/6a51d5fd96a4cbc47149db7a5a8da142a0d55ce6) Thanks [@wyller](https://github.com/wyller)! - The Rawcode lookup reads the map folder again when one of its files changes: once `minInterval` (one second by default) has passed since its last check, a lookup compares the modification times of the Object data files, their Skin files, `war3map.wts`, `war3map.w3i` and the `reforged-builtins` index, and rebuilds its model when one changed, appeared or disappeared. An object saved in the World Editor is known at the next lookup, without a build. A read that fails makes the lookup unavailable, and each later check reads the files again until one succeeds.

- [#603](https://github.com/phmilk/reforged-ts/pull/603) [`3b15944`](https://github.com/phmilk/reforged-ts/commit/3b15944f9a6e5c747e753aaeadca15d902fed288) Thanks [@wyller](https://github.com/wyller)! - `generateObjects` writes a `FourCC` overload for each Built-in object the map modifies. Its TSDoc gives the game's name and the map's: "Footman (`hfoo`), a Built-in unit of Patch 3.0.0, named Militia in this map". The overload names the object's `reforged-builtins` constant, and the object gets no Custom constant. With the overloads of `reforged-builtins` turned on, the map's overload wins. A Rawcode two kinds share, such as a Custom buff and a Custom destructable at `B000`, gets no overload: `FourCC("B000")` stays an `UnknownRawcode`, and each kind keeps its constant with its exact kind. A Custom Rawcode equal to a Built-in object's is read as the map's Custom object, with a warning.

- [#599](https://github.com/phmilk/reforged-ts/pull/599) [`bde374e`](https://github.com/phmilk/reforged-ts/commit/bde374e1ff61beac01391e7568461a2132bf7082) Thanks [@wyller](https://github.com/wyller)! - `generateObjects` reads the Custom objects of every Object kind ([#585](https://github.com/phmilk/reforged-ts/issues/585)): items (`war3map.w3t`), abilities (`.w3a`), buffs (`.w3h`), destructables (`.w3b`), doodads (`.w3d`) and upgrades (`.w3q`), with their `war3mapSkin` counterparts, join the units. Each gets its `FourCC` overload, typed by its kind, and its constant in its kind's module: `CustomItems`, `CustomAbilities`, `CustomBuffs`, `CustomDestructables`, `CustomDoodads` and `CustomUpgrades`, so `UnitAddAbility(u, CustomAbilities.FrostStorm_A000)` compiles and a Custom item where a unit is expected does not. Names follow the Object Editor as `reforged-builtins` does: a buff without an editor name is named by its tooltip's title, and an upgrade by its first level's name.

- [#609](https://github.com/phmilk/reforged-ts/pull/609) [`e963600`](https://github.com/phmilk/reforged-ts/commit/e963600c4c67c82bf8c531d19aa554078be8410d) Thanks [@wyller](https://github.com/wyller)! - The README documents the map's objects: what `generateObjects` reads and the files it writes, the constants' names, the overloads' precedence, a Rawcode two kinds share, the optional peer `reforged-builtins`, every warning, and the check-time cost of the map's overloads, measured at 500 Custom objects (0.45 to 2.3 ms per literal `FourCC` call, depending on the machine's load). The Rawcodes guide gains a section on Custom objects, with how a Map project generated earlier turns them on.

- [#604](https://github.com/phmilk/reforged-ts/pull/604) [`ecf4d13`](https://github.com/phmilk/reforged-ts/commit/ecf4d13381643be7efd0bd26cbb17c3ec923ad92) Thanks [@wyller](https://github.com/wyller)! - `generateObjects` names the objects of a map saved by an older World Editor or by another tool ([#587](https://github.com/phmilk/reforged-ts/issues/587)): Object data files of format versions 1 and 2 are read beside version 3, and a levelled modification of an abilities, doodads or upgrades file is read with its value type before its level and data pointer, as the game writes it, so such a file is no longer misread.

## 1.0.0-alpha.0

### Major Changes

- [#504](https://github.com/phmilk/reforged-ts/pull/504) [`84adfb0`](https://github.com/phmilk/reforged-ts/commit/84adfb02694952dde50ec4b9cb721698fa647e72) Thanks [@wyller](https://github.com/wyller)! - First release of `reforged-map`, which reads a Map project's map folder at build time. `generateEditorGlobals(mapFolder)` returns the declarations and the Lua stub of its Editor globals, each `gg_` and `udg_` global the World Editor declares, with the warnings for the author; a missing map folder or `war3map.lua` throws a `MapFolderError`. A `udg_` variable whose Variable Editor type names an Object kind is declared with that Object kind, read from `war3map.wtg`: a Unit-Type is a `Rawcode<"unit">`, a Tech-Type a `Rawcode<"unit" | "upgrade">`, an array a `Record<number, Rawcode<…>>`, and an Order stays `number`. It needs `reforged-types` 1.0.0-alpha.5 or later as a peer, the first that declares the Rawcode types. Install it with `pnpm add -D reforged-map@next`; the Template calls it from its build once it takes the package up.
